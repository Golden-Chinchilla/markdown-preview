# realid-identity-lifecycle — 需求规格

**创建日期**: 2026-06-03
**状态**: 草稿

## 引言

RealID 提供从注册、登录、护照升级、密钥轮换、设备迁移、注销、回滚到社交恢复和实时核身的身份生命周期能力。本文档把现有代码反向提取出的 `REQ-*` 洞察整理为 EARS 格式需求，并保留源码洞察引用。[[ REQ-003, REQ-004, REQ-006, REQ-008, REQ-011, REQ-015 ]]

本文档描述系统必须完成的可验证行为，不描述具体实现路径。无法从代码中确认的产品规则保留在 `UNKNOWN` 标记和“范围外”章节中。[[ ARCH-002, ARCH-003 ]]

## 用户故事

- US-1: 作为新用户，我希望通过邮箱验证和本地密钥注册 Real ID，以便获得可上链验证的 DID 身份。[[ REQ-001, REQ-002, REQ-003 ]]
- US-2: 作为已注册用户，我希望通过设备指纹或邮箱登录，以便进入我的 Real ID 账户。[[ REQ-004 ]]
- US-3: 作为已登录用户，我希望通过护照证明升级身份类型，以便获得 seed 用户身份。[[ REQ-006, REQ-016 ]]
- US-4: 作为已登录用户，我希望轮换本地密钥，以便在密钥更换后继续使用同一个 Real ID。[[ REQ-007, REQ-017 ]]
- US-5: 作为已登录用户，我希望把 Real ID 迁移到新设备，以便在新设备上继续使用账户。[[ REQ-008 ]]
- US-6: 作为已登录用户，我希望注销 Real ID，以便终止该身份的有效状态。[[ REQ-009 ]]
- US-7: 作为系统操作者，我希望在链上数据比对失败时回滚最近一次身份动作，以便降低端链状态不一致的影响。[[ REQ-010 ]]
- US-8: 作为遗失设备的用户，我希望通过社交恢复找回身份，以便重新获得 Real ID 控制权。[[ REQ-011 ]]
- US-9: 作为 RealID 用户，我希望向好友发起实时核身，以便确认对方身份状态。[[ REQ-012 ]]
- US-10: 作为 RealID 用户，我希望管理好友、群组和消息，以便参与社交恢复和核身流程。[[ REQ-013, REQ-014 ]]

## 需求

### 功能需求

#### FR-1: 注册与上链

##### REQ-RID-01: 注册邮箱验证码 [*]

**类型**: 事件驱动
**优先级**: P0

当用户使用邮箱地址发起注册时，系统应签发注册邮箱验证码会话。[[ REQ-001 ]]

**验收标准**:
- [ ] AC-01.1: 发送注册验证码成功时，响应包含非空 `emailVerificationSessionId`。[[ REQ-001 ]]
- [ ] AC-01.2: 邮箱注册类型可被响应数据标识为 `registrationType`。[[ REQ-001 ]]
- [ ] AC-01.3: 验证码校验成功时，响应包含非空 `emailVerificationValidSessionId`。[[ REQ-001 ]]

##### REQ-RID-02: 注册资料校验 [*]

**类型**: 事件驱动
**优先级**: P0

当用户提交已验证的注册会话和资料数据时，系统应创建注册进度会话。[[ REQ-002 ]]

**验收标准**:
- [ ] AC-02.1: 校验请求包含邮箱有效会话、真实姓名、头像、DID ID 和 DID ID Key。[[ REQ-002 ]]
- [ ] AC-02.2: 校验成功时，响应包含非空 `userRegistrationProgressSessionId`。[[ REQ-002 ]]
- [ ] AC-02.3: 校验成功时，响应包含非空 `accountId`。[[ REQ-002 ]]

##### REQ-RID-03: 注册上链提交 [*]

**类型**: 事件驱动
**优先级**: P0

当注册资料校验通过时，系统应提交已签名的 DID 注册动作。[[ REQ-003 ]]

**验收标准**:
- [ ] AC-03.1: 注册上链材料包含 `dataToSign`、DID 文档 payload 和 DID 文档 payload hash。[[ REQ-003 ]]
- [ ] AC-03.2: 注册上链材料包含用户签名、设备签名和增强用户签名。[[ REQ-003, REQ-017 ]]
- [ ] AC-03.3: 链上注册动作使用 actionCode `1`。[[ REQ-003, REQ-015 ]]
- [ ] AC-03.4: 已注册的 DID ID Key 再次注册时，链上状态机拒绝该动作。[[ REQ-003, REQ-015 ]]

##### REQ-RID-04: 注册结果比对

**类型**: 事件驱动
**优先级**: P0

当注册动作达到链上确认状态时，系统应将链上 DID 文档与端侧期望 DID 文档进行比对。[[ REQ-003 ]]

**验收标准**:
- [ ] AC-04.1: 比对成功时，系统上传注册比对结果。[[ REQ-003 ]]
- [ ] AC-04.2: 比对失败时，系统发起注册回滚或用户回滚。[[ REQ-003, REQ-010 ]]
- [ ] AC-04.3: 比对结果关联注册进度会话或链上请求标识。[[ REQ-003 ]]

#### FR-2: 登录与安全通道

##### REQ-RID-05: 传输安全通道 [*]

**类型**: 事件驱动
**优先级**: P0

当客户端启动受保护业务会话时，系统应建立加密传输会话。[[ REQ-005 ]]

**验收标准**:
- [ ] AC-05.1: 协商成功时，响应包含 `transSessionId`。[[ REQ-005 ]]
- [ ] AC-05.2: 协商成功时，响应包含服务端公钥包、加密 nonce 和响应签名。[[ REQ-005 ]]
- [ ] AC-05.3: 后续业务请求携带传输会话标识。[[ REQ-005 ]]
- [ ] AC-05.4: 后续业务请求携带加密业务数据。[[ REQ-005 ]]

##### REQ-RID-06: 设备指纹登录 [*]

**类型**: 事件驱动
**优先级**: P0

当已注册设备提交匹配的本地身份数据时，系统应创建登录有效会话。[[ REQ-004 ]]

**验收标准**:
- [ ] AC-06.1: 设备指纹登录成功时，响应包含 `loginValidSessionId`。[[ REQ-004 ]]
- [ ] AC-06.2: 设备指纹登录成功时，响应包含账户状态。[[ REQ-004 ]]
- [ ] AC-06.3: 本地设备 ID 与当前设备 ID 不一致时，系统返回设备不匹配结果。[[ REQ-004 ]]
- [ ] AC-06.4: 重装残留安全身份未确认时，系统阻止自动登录。[[ REQ-004 ]]

##### REQ-RID-07: 邮箱登录

**类型**: 事件驱动
**优先级**: P0

当已注册用户完成邮箱登录验证时，系统应创建登录有效会话。[[ REQ-004 ]]

**验收标准**:
- [ ] AC-07.1: 邮箱登录成功时，响应包含 `loginValidSessionId`。[[ REQ-004 ]]
- [ ] AC-07.2: 邮箱登录成功时，响应包含账户状态。[[ REQ-004 ]]
- [ ] AC-07.3: 邮箱未注册时，系统返回邮箱登录要求或账号不存在错误。[[ REQ-004 ]]

##### REQ-RID-08: 登录态复用限制

**类型**: 状态驱动
**优先级**: P0

在本地账户不处于可复用运行态期间，系统应阻止复用本地登录会话。[[ REQ-004, REQ-020 ]]

**验收标准**:
- [ ] AC-08.1: 账户处于密钥更新状态时，系统不复用本地登录态。[[ REQ-004, REQ-020 ]]
- [ ] AC-08.2: 账户处于注销状态时，系统不复用本地登录态。[[ REQ-004 ]]
- [ ] AC-08.3: 本地登录态缺少必要身份数据时，系统返回缺少本地身份结果。[[ REQ-004 ]]

#### FR-3: 端侧密钥

##### REQ-RID-09: 端侧密钥操作 [*]

**类型**: 通用型
**优先级**: P0

系统应提供端侧密钥生成、公钥读取、签名、验签和密钥删除能力。[[ REQ-017 ]]

**验收标准**:
- [ ] AC-09.1: 系统可生成 Ed25519 密钥对。[[ REQ-017 ]]
- [ ] AC-09.2: 系统可生成 P-256 安全区密钥。[[ REQ-017 ]]
- [ ] AC-09.3: 系统可返回指定 key tag 的公钥。[[ REQ-017 ]]
- [ ] AC-09.4: 系统可对消息或 digest 执行签名。[[ REQ-017 ]]
- [ ] AC-09.5: 批量签名的 key tag 数量与 message 数量不一致时，系统返回失败。[[ REQ-017 ]]

##### REQ-RID-10: 生物识别签名会话

**类型**: 事件驱动
**优先级**: P1

当敏感本地签名要求用户在场确认时，系统应启动生物识别授权会话。[[ REQ-017 ]]

**验收标准**:
- [ ] AC-10.1: 生物识别会话开始成功后，敏感签名流程可继续。[[ REQ-017 ]]
- [ ] AC-10.2: 生物识别会话失败时，敏感签名流程返回失败。[[ REQ-017 ]]
- [ ] AC-10.3: 敏感签名流程结束后，系统清理生物识别会话。[[ REQ-017 ]]

#### FR-4: 护照升级与 ZKP

##### REQ-RID-11: 护照升级校验 [*]

**类型**: 事件驱动
**优先级**: P0

当已登录用户发起护照升级时，系统应在上链提交前校验护照证明材料。[[ REQ-006 ]]

**验收标准**:
- [ ] AC-11.1: 护照升级前，系统检查未完成密钥轮换。[[ REQ-006, REQ-020 ]]
- [ ] AC-11.2: 护照升级前，系统确认护照明文个人信息已删除。[[ REQ-006 ]]
- [ ] AC-11.3: 校验请求包含护照算法、identifier、护照有效期和签发国。[[ REQ-006 ]]
- [ ] AC-11.4: 校验成功时，响应包含 `userUpdateProgressSessionId`。[[ REQ-006 ]]

##### REQ-RID-12: 护照 ZKP 上链校验 [*]

**类型**: 事件驱动
**优先级**: P0

当护照升级动作提交到链上时，系统应校验护照证明。[[ REQ-006, REQ-016 ]]

**验收标准**:
- [ ] AC-12.1: 护照升级链上动作使用 actionCode `2`。[[ REQ-006, REQ-015 ]]
- [ ] AC-12.2: ZK proof 为空时，链上状态机拒绝升级。[[ REQ-006, REQ-016 ]]
- [ ] AC-12.3: 证明算法未配置 verifier 时，证明校验失败。[[ REQ-016 ]]
- [ ] AC-12.4: 公开信号超出 BN254 标量域时，证明校验失败。[[ REQ-016 ]]

#### FR-5: 密钥轮换

##### REQ-RID-13: 用户密钥轮换 [*]

**类型**: 事件驱动
**优先级**: P0

当已登录用户发起密钥轮换时，系统应提交已签名的密钥轮换动作。[[ REQ-007 ]]

**验收标准**:
- [ ] AC-13.1: 密钥轮换前，系统读取登录会话。[[ REQ-007 ]]
- [ ] AC-13.2: 系统生成新用户公钥。[[ REQ-007, REQ-017 ]]
- [ ] AC-13.3: 系统生成新增强用户公钥。[[ REQ-007, REQ-017 ]]
- [ ] AC-13.4: 系统生成新设备公钥。[[ REQ-007, REQ-017 ]]
- [ ] AC-13.5: 链上密钥轮换动作使用 actionCode `3`。[[ REQ-007, REQ-015 ]]

##### REQ-RID-14: 密钥轮换恢复

**类型**: 状态驱动
**优先级**: P0

在密钥轮换 pending 记录存在期间，系统应恢复该 pending 密钥轮换动作。[[ REQ-007, REQ-020 ]]

**验收标准**:
- [ ] AC-14.1: 存在密钥轮换 pending 时，系统不提交新的密钥轮换动作。[[ REQ-007, REQ-020 ]]
- [ ] AC-14.2: 密钥轮换恢复使用原 pending 中的 DID 和请求上下文。[[ REQ-007, REQ-020 ]]
- [ ] AC-14.3: 密钥轮换比对失败时，系统触发回滚路径。[[ REQ-007, REQ-010 ]]

#### FR-6: 设备迁移

##### REQ-RID-15: 新设备迁移二维码

**类型**: 事件驱动
**优先级**: P0

当新设备准备迁入身份时，系统应创建已签名的迁移二维码 payload。[[ REQ-008 ]]

**验收标准**:
- [ ] AC-15.1: QR payload 包含迁移会话标识。[[ REQ-008 ]]
- [ ] AC-15.2: QR payload 包含新设备 ID。[[ REQ-008 ]]
- [ ] AC-15.3: QR payload 包含新设备公钥材料。[[ REQ-008 ]]
- [ ] AC-15.4: QR payload 包含二维码签名。[[ REQ-008 ]]
- [ ] AC-15.5: 首次读取新设备密钥材料失败时，系统执行一次重试。[[ REQ-008 ]]

##### REQ-RID-16: 旧设备迁移发起 [*]

**类型**: 事件驱动
**优先级**: P0

当旧设备提交扫码得到的迁移二维码 payload 时，系统应创建设备迁移进度记录。[[ REQ-008 ]]

**验收标准**:
- [ ] AC-16.1: 迁移发起前，系统检查旧设备登录会话。[[ REQ-008 ]]
- [ ] AC-16.2: 迁移发起前，系统检查未完成密钥轮换。[[ REQ-008, REQ-020 ]]
- [ ] AC-16.3: 迁移记录包含旧设备 ID。[[ REQ-008 ]]
- [ ] AC-16.4: 迁移记录包含新设备 ID。[[ REQ-008 ]]
- [ ] AC-16.5: 二维码 TLV 为空时，系统返回业务错误。[[ REQ-008 ]]

##### REQ-RID-17: 设备迁移上链与同步 [*]

**类型**: 事件驱动
**优先级**: P0

当设备迁移进度记录满足链上确认条件时，系统应提交已签名的设备迁移动作。[[ REQ-008 ]]

**验收标准**:
- [ ] AC-17.1: 普通设备迁移链上动作使用 actionCode `5`。[[ REQ-008, REQ-015 ]]
- [ ] AC-17.2: 迁移审批链上动作使用 actionCode `7`。[[ REQ-008, REQ-015 ]]
- [ ] AC-17.3: 迁移状态查询返回迁移状态。[[ REQ-008 ]]
- [ ] AC-17.4: 迁移状态查询返回账户同步状态。[[ REQ-008 ]]
- [ ] AC-17.5: 迁移比对成功时，系统同步新设备登录态。[[ REQ-008 ]]

#### FR-7: 注销与回滚

##### REQ-RID-18: Real ID 注销 [*]

**类型**: 事件驱动
**优先级**: P0

当活动用户请求注销 Real ID 时，系统应提交已签名的注销动作。[[ REQ-009 ]]

**验收标准**:
- [ ] AC-18.1: 已注销账号不得发起注销。[[ REQ-009 ]]
- [ ] AC-18.2: 非运行态账号不得发起注销。[[ REQ-009 ]]
- [ ] AC-18.3: 注销前，系统检查未完成密钥轮换。[[ REQ-009, REQ-020 ]]
- [ ] AC-18.4: 注销前，系统检查本地 key set 与链上 key set 一致。[[ REQ-009 ]]
- [ ] AC-18.5: 链上注销动作使用 actionCode `4`。[[ REQ-009, REQ-015 ]]

##### REQ-RID-19: 用户回滚 [*]

**类型**: 事件驱动
**优先级**: P0

当生命周期动作后的链上 DID 文档比对失败时，系统应提交用户回滚动作。[[ REQ-010 ]]

**验收标准**:
- [ ] AC-19.1: 回滚请求包含来源 actionCode。[[ REQ-010 ]]
- [ ] AC-19.2: 回滚请求包含来源 requestId 或来源 txHash。[[ REQ-010 ]]
- [ ] AC-19.3: 回滚请求包含 DID 文档比对详情。[[ REQ-010 ]]
- [ ] AC-19.4: 已存在回滚 pending 时，系统不重复提交回滚。[[ REQ-010, REQ-020 ]]
- [ ] AC-19.5: 链上无可回滚最近动作时，链上状态机拒绝无效化。[[ REQ-010, REQ-015 ]]

#### FR-8: 社交恢复与实时核身

##### REQ-RID-20: 社交恢复预检

**类型**: 事件驱动
**优先级**: P1

当用户使用邮箱地址发起社交恢复时，系统应评估本地 Real ID 的恢复资格。[[ REQ-011 ]]

**验收标准**:
- [ ] AC-20.1: 本机无 Real ID 时，系统允许继续恢复。[[ REQ-011 ]]
- [ ] AC-20.2: 本机同邮箱 Real ID 可登录时，系统建议登录。[[ REQ-011 ]]
- [ ] AC-20.3: 本机不同邮箱 Real ID 存在时，系统提示本地数据会被清理。[[ REQ-011 ]]
- [ ] AC-20.4: 本机异常生命周期状态存在时，系统要求用户确认后继续恢复。[[ REQ-011 ]]

##### REQ-RID-21: 社交恢复确认 [*]

**类型**: 事件驱动
**优先级**: P0

当社交恢复签名满足恢复流程要求时，系统应确认恢复后的 Real ID 数据。[[ REQ-011 ]]

**验收标准**:
- [ ] AC-21.1: 恢复邮箱验证成功时，系统返回恢复验证码 session。[[ REQ-011 ]]
- [ ] AC-21.2: 恢复发起成功时，系统返回恢复会话。[[ REQ-011 ]]
- [ ] AC-21.3: 恢复确认成功时，响应包含 `ridacId`。[[ REQ-011 ]]
- [ ] AC-21.4: 恢复确认成功时，响应包含 `didId`。[[ REQ-011 ]]
- [ ] AC-21.5: 终端数据核验失败时，系统返回需要重启恢复的结果。[[ REQ-011 ]]

##### REQ-RID-22: 实时核身

**类型**: 事件驱动
**优先级**: P1

当用户向好友发起实时核身时，系统应创建核身消息。[[ REQ-012 ]]

**验收标准**:
- [ ] AC-22.1: 发起成功时，响应包含 `serialNumber`。[[ REQ-012 ]]
- [ ] AC-22.2: 发起成功时，响应包含服务端验证码。[[ REQ-012 ]]
- [ ] AC-22.3: 验证码不一致时，系统标记核身失败。[[ REQ-012 ]]
- [ ] AC-22.4: 验证码一致时，系统返回 `verifyStatus = 00`。[[ REQ-012 ]]
- [ ] AC-22.5: 发起方可分页查询实时核身记录。[[ REQ-012 ]]

##### REQ-RID-23: 社交关系与消息

**类型**: 通用型
**优先级**: P2

系统应提供社交链接、群组和消息工作流，以支撑身份协作。[[ REQ-013, REQ-014 ]]

**验收标准**:
- [ ] AC-23.1: 系统支持二维码校验。[[ REQ-013 ]]
- [ ] AC-23.2: 系统支持添加社交链接。[[ REQ-013 ]]
- [ ] AC-23.3: 系统支持好友列表查询。[[ REQ-013 ]]
- [ ] AC-23.4: 系统支持群组创建确认。[[ REQ-013 ]]
- [ ] AC-23.5: 系统支持消息列表查询。[[ REQ-014 ]]
- [ ] AC-23.6: 系统支持消息已读状态更新。[[ REQ-014 ]]

#### FR-9: Pending 恢复

##### REQ-RID-24: 生命周期 pending 恢复 [*]

**类型**: 状态驱动
**优先级**: P0

在生命周期 pending 记录存在期间，系统应先恢复 pending 生命周期流程，再创建新流程。[[ REQ-020 ]]

**验收标准**:
- [ ] AC-24.1: 升级 pending 存在时，系统优先恢复升级流程。[[ REQ-020 ]]
- [ ] AC-24.2: 密钥轮换 pending 存在时，系统优先恢复密钥轮换流程。[[ REQ-020 ]]
- [ ] AC-24.3: 设备迁移 pending 存在时，系统优先恢复设备迁移流程。[[ REQ-020 ]]
- [ ] AC-24.4: 注销 pending 存在时，系统不发起新的注销流程。[[ REQ-020 ]]
- [ ] AC-24.5: 回滚 pending 存在时，系统不发起新的回滚流程。[[ REQ-020 ]]

### 非功能需求

##### NFR-01: 链上动作授权 [*]

**类型**: 通用型
**优先级**: P0

系统应拒绝未授权 relayer 发起的生命周期链上动作。[[ REQ-015 ]]

**验收标准**:
- [ ] AC-NFR-01.1: 未授权 relayer 调用注册动作时，链上状态机拒绝交易。[[ REQ-015 ]]
- [ ] AC-NFR-01.2: 未授权 relayer 调用更新动作时，链上状态机拒绝交易。[[ REQ-015 ]]
- [ ] AC-NFR-01.3: 未授权 relayer 调用迁移动作时，链上状态机拒绝交易。[[ REQ-015 ]]

##### NFR-02: 链上重放保护 [*]

**类型**: 通用型
**优先级**: P0

系统应拒绝 nonce 无效或 deadline 过期的生命周期链上动作。[[ REQ-015 ]]

**验收标准**:
- [ ] AC-NFR-02.1: nonce 与链上期望值不一致时，链上状态机拒绝交易。[[ REQ-015 ]]
- [ ] AC-NFR-02.2: deadline 早于当前链上时间时，链上状态机拒绝交易。[[ REQ-015 ]]

##### NFR-03: DID 文档可追溯

**类型**: 通用型
**优先级**: P0

系统应通过 Registry 事件源发出 DID 文档状态变更。[[ REQ-015 ]]

**验收标准**:
- [ ] AC-NFR-03.1: 注册成功时，Registry 记录 DID 文档属性变更事件。[[ REQ-015 ]]
- [ ] AC-NFR-03.2: 密钥轮换成功时，Registry 记录 DID 文档密钥属性变更事件。[[ REQ-015 ]]
- [ ] AC-NFR-03.3: 注销成功时，Registry 记录 DID 文档撤销相关事件。[[ REQ-015 ]]

##### NFR-04: 端链一致性保护 [*]

**类型**: 通用型
**优先级**: P0

系统应在生命周期动作链上确认后，比对端侧期望 DID 文档与链上解析 DID 文档。[[ REQ-003, REQ-006, REQ-007, REQ-008, REQ-010 ]]

**验收标准**:
- [ ] AC-NFR-04.1: 注册确认后执行 DID 文档比对。[[ REQ-003 ]]
- [ ] AC-NFR-04.2: 护照升级确认后执行 DID 文档比对。[[ REQ-006 ]]
- [ ] AC-NFR-04.3: 密钥轮换确认后执行 DID 文档比对。[[ REQ-007 ]]
- [ ] AC-NFR-04.4: 设备迁移确认后执行 DID 文档比对。[[ REQ-008 ]]
- [ ] AC-NFR-04.5: 比对失败时触发回滚路径。[[ REQ-010 ]]

##### NFR-05: 敏感数据约束 [*]

**类型**: 通用型
**优先级**: P0

当护照明文个人数据未确认删除时，系统应阻止护照升级继续执行。[[ REQ-006 ]]

**验收标准**:
- [ ] AC-NFR-05.1: 护照明文个人信息未确认删除时，升级流程返回失败。[[ REQ-006 ]]
- [ ] AC-NFR-05.2: 护照明文个人信息未确认删除时，系统不提交升级 validation。[[ REQ-006 ]]

##### NFR-06: 匿名证明执行约束

**类型**: 通用型
**优先级**: P2

系统应通过原生证明 SDK 生成匿名群组授权证明材料。[[ REQ-018 ]]

**验收标准**:
- [ ] AC-NFR-06.1: 证明生成输入包含群组成员身份承诺列表。[[ REQ-018 ]]
- [ ] AC-NFR-06.2: 证明生成输入包含当前身份私钥。[[ REQ-018 ]]
- [ ] AC-NFR-06.3: 证明生成输入包含消息、scope 和 Merkle tree depth。[[ REQ-018 ]]
- [ ] AC-NFR-06.4: 调用方释放 proof SDK 返回的字符串。[[ REQ-018 ]]

## 成功标准

- SC-1: 新用户完成邮箱验证码、注册资料校验、注册上链、DID 文档比对后，系统产生可登录 Real ID。[[ REQ-001, REQ-002, REQ-003, REQ-004 ]]
- SC-2: 已注册用户在设备 ID 匹配时完成设备指纹登录，并获得登录有效会话。[[ REQ-004 ]]
- SC-3: 已登录用户完成护照升级 validation、ZKP 上链校验、DID 文档比对后，系统记录升级完成状态。[[ REQ-006, REQ-016 ]]
- SC-4: 已登录用户完成密钥轮换后，链上 DID 文档中的 key set 与端侧期望 key set 一致。[[ REQ-007, REQ-015 ]]
- SC-5: 已登录用户完成设备迁移后，新设备获得可用登录态，旧设备迁移流程闭环。[[ REQ-008 ]]
- SC-6: 已登录用户完成注销后，链上 DID 状态进入注销或无效状态。[[ REQ-009, REQ-015 ]]
- SC-7: 任一生命周期动作 DID 文档比对失败时，系统创建或恢复用户回滚流程。[[ REQ-010, REQ-020 ]]
- SC-8: 用户通过社交恢复确认和终端数据核验后，系统返回恢复后的 DID 数据。[[ REQ-011 ]]
- SC-9: 用户向好友发起实时核身后，被核身方提交匹配验证码时核身状态为成功。[[ REQ-012 ]]
