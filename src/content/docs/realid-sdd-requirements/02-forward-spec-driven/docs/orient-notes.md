# realid-identity-lifecycle — 定向说明

## 问题陈述

当前项目已有 Flutter、iOS 原生、Java 后端和 Solidity 合约代码，但初版需求文档偏叙述型，缺少正向 spec-driven 要求的 EARS 句式、验收标准、用户故事、非功能需求、范围外、术语表和追溯矩阵。

## 利益相关者 / 用户角色

- 新用户：完成注册并获得 Real ID。
- 已注册用户：登录、升级、轮换密钥、迁移设备、注销账户。
- 遗失设备用户：通过社交恢复找回身份。
- 好友/群组成员：参与社交恢复和实时核身。
- 系统操作者：维护链上生命周期动作、回滚和 DID 文档一致性。
- 开发/测试人员：依据可测试需求补齐设计、任务和测试。

## 功能区域

1. 注册与上链。
2. 登录与传输安全。
3. 端侧密钥与生物识别。
4. 护照升级与 ZKP。
5. 密钥轮换。
6. 设备迁移。
7. 注销与回滚。
8. 社交恢复与实时核身。
9. 社交关系、群组和消息。
10. 生命周期 pending 恢复。

## 约束与非功能关注点

- 需求必须保留来自 `analysis/insights.md` 的可追溯引用。
- 需求应采用 EARS 句式。
- 每条需求应有可测试验收标准。
- 安全关键能力需要 `[*]` 标记。
- 无法从代码确认的规则应进入“范围外”或“未确认项”。
- 当前输出仍属于反向需求整理，不应补充无源码依据的产品规则。
